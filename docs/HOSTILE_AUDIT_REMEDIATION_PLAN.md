# PHASE 1: Studio Panel (CRITICAL — user-facing error)

## Problem
Studio panel shows an error. The user reports "nothing in studio works correctly, it shows a big error."

## Root Cause Analysis

After examining the full code path:

1. `StudioPanel.tsx` calls `loadOutputs(notebookId)` on mount
2. This calls `listStudioOutputs(notebookId)` via Tauri invoke
3. Backend `list_studio_outputs` calls `state.with_notebook_db(&notebook_id, |db| db.list_studio_outputs()?)`
4. `NotebookDb::list_studio_outputs()` runs `SELECT * FROM studio_outputs ORDER BY created_at DESC`
5. The `studio_outputs` table is created in `migrations.rs` line 264

**Likely root cause**: The `studio_outputs` table migration exists but may not have run on existing notebook databases. When a notebook was created before the studio migration was added, the table won't exist, causing a SQL error. Additionally, there's no error handling in the Rust backend to recover — if the table doesn't exist, the SQL call fails with a generic error that propagates to the frontend.

**Secondary issue**: When no notebook is selected (notebookId is null/empty), the command fails immediately, and the frontend shows the raw error text in the panel.

## Fixes

### 1.1. Add migration resilience
- File: `src-tauri/src/db/migrations.rs`
- Add an idempotent `CREATE TABLE IF NOT EXISTS studio_outputs` check that runs on notebook DB open, not just during initial migration
- OR add a migration version bump to force schema migration for existing notebooks

### 1.2. Add defensive error handling in list_studio_outputs
- File: `src-tauri/src/db/notebook_db/mod.rs`
- In `list_studio_outputs()`, catch SQL "no such table" errors and return an empty vec instead of failing
- Log a warning about missing table so operator knows migration is needed

### 1.3. Fix frontend error handling
- File: `src/stores/studioStore.ts`
- In `loadOutputs()`, catch errors and set `outputs = []` with a user-friendly error message instead of crashing
- File: `src/components/studio/StudioPanel.tsx`
- Show a helpful message when no outputs exist: "No Studio outputs yet. Generate one by selecting an output type and clicking Generate."
- Show a specific message when notebook has no sources: "Import sources first before using Studio."

### 1.4. Add studio migration to db open path
- File: `src-tauri/src/db/notebook_db/mod.rs`
- On `NotebookDb::open()`, run `CREATE TABLE IF NOT EXISTS studio_outputs (...)` if it doesn't exist
- This ensures existing notebooks get the table without requiring a full migration

### 1.5. Verify studio with actual data
- Write a test that: creates notebook → imports a source → generates studio output → lists outputs → exports output
- File: `src-tauri/src/commands/studio.rs` (tests section)
- File: `src-tauri/src/studio/mod.rs` (tests section — already has good tests)
